# Desktop Dock 阶段 1 计划

P1 从本地 Git 基线 `64dd5e1` 开始。PRD、技术设计和 P0 验证确认了 WPF 透明无边框窗口、手动管理项目、Shell 启动、版本化配置等边界。正式项目使用 `net10.0-windows`。本机系统级工具链缺少 .NET 10，使用经过校验的 Windows x64 便携 SDK 构建和测试。

## 实现顺序

1. 建立单进程 WPF 应用，按业务与配置、Windows 集成、窗口界面分开。窗口采用 Per-Monitor V2、透明无边框样式和非激活展示。P1 一个 Dock 支持四边及浮动位置。工作区尺寸限制可见范围。
2. 实现用户选择或拖入项目、编辑、原生 Shell 打开和移除引用。配置保存稳定 ID、排列顺序、外观、位置和图标覆盖。配置写入先校验，采用同目录临时文件和原子替换。未来格式无法识别时保留文件。
3. 异步提取 EXE、LNK、文件和文件夹图标，按输入和尺寸缓存。自定义图标只修改 Dock 显示引用。拖拽项目和移动 Dock 分别在独立命中区域处理，位置锁作用于手柄。设置窗口关闭后后台继续运行，通知区域提供显隐和退出入口。
4. 用 Release 可执行文件和独立测试配置在 Windows 11 验证。应用户要求，为应用提供 `--mcp-stdio` 测试模式，复用正式操作并读取真实 WPF 窗口渲染。测试只使用显式创建或选定的目标。记录真实启动、原文件哈希、顺序和窗口状态的证据，并更新验收与 TODO。系统文件选择器、物理鼠标悬停和 Explorer/OLE 拖放的结论独立记录。

## 验收矩阵

| 编号 | 验证 | 通过判据 |
| --- | --- | --- |
| P1-01 | EXE | 添加临时受控 EXE，从 Dock 打开并观察其启动证据。 |
| P1-02 | LNK | 添加指向受控目标的真实 LNK，验证 Shell 保留快捷方式启动语义。 |
| P1-03 | 普通文件和文件夹 | 选择器或资源管理器拖入后出现在 Dock，可用关联应用打开。 |
| P1-04 | 网址 | 校验 HTTP/HTTPS，打开测试网址并观察系统默认浏览器。 |
| P1-05 | 图标 | 等待异步加载，验证原始图标、文件类型图标和自定义图标显示。 |
| P1-06 | Tooltip | 真实鼠标悬停项目，观察显示相应名称。 |
| P1-07 | 排序 | 拖动图标到另一图标的插入位置，检查反馈与实际顺序。 |
| P1-08 | 移动与锁定 | 从 Dock 空白区进入手柄并移动，检查项目顺序和窗口位置分别更新。验证全局与单 Dock 锁。 |
| P1-09 | 配置恢复 | 修改尺寸、停靠或浮动位置和项目配置，退出并重启验证恢复。 |
| P1-10 | 引用移除 | 移除 Dock 项目，检查目标仍可访问且文件 SHA-256 一致。 |
| P1-11 | 生命周期与配置安全 | 设置窗口关闭后 Dock 可用，显隐可恢复。验证无效路径、损坏配置、未来版本和写入失败的处理。 |

范围限于基础常驻 Dock。自动隐藏、热区、全局快捷键、全屏避让、桌面图标修改、分组与主题编辑器留待后续阶段。
